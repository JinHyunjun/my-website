03 · The Trigger

관심이 생긴 세 개의 TableFactor

괄호가 있다는 점은 같지만 GlueSQL이 책임지는 의미는 서로 다릅니다.

지원되는 Table Function

SELECT * FROM SERIES(3);
✓인자 3을 실제 크기로 사용

Dictionary Table + 인자

SELECT * FROM GLUE_TABLES(1);
!인자를 받을 기능이 없음

일반 Table + 인자

SELECT * FROM Foo(1);
!지원하지 않는 Table Function
기존 코드는 두 번째와 세 번째 입력의 괄호 안 정보를 조용히 버릴 수 있었다.
SERIES는 실제로 인자를 사용하는 기능입니다. 반면 GLUE_TABLES는 Dictionary table이고 Foo는 일반 table입니다. 기존 main에서는 unsupported args가 있어도 일반 table 또는 dictionary로 번역될 수 있었습니다.

Option<TableFunctionArgs>이므로 괄호가 없으면 None, 있으면 Some(...)입니다.

제가 처음 이해하기 어려웠던 부분입니다. args는 Option이기 때문에 None과 Some으로 인자의 유무를 표현합니다. 내부 값을 아직 보지 않더라도 존재 여부만으로 지원 여부를 판단할 수 있습니다.

05 · Root Cause

_는 편리했지만, 기능 계약까지 지워버렸다

upstream/mainbefore
match (object_name.as_str(), args) {
    ("SERIES", Some(...)) => ...

    ("GLUE_TABLES", _) =>
        TableFactor::Dictionary { ... },

    _ => TableFactor::Table { ... },
}
STEP 01

_가 None과 Some을 모두 받음

STEP 02

Dictionary와 일반 Table AST에는 인자를 보관할 필드가 없음

STEP 03

입력의 괄호와 인자가 오류 없이 사라짐

문법적으로 읽을 수 있다는 것과 GlueSQL이 지원한다는 것은 다르다.
핵심은 Rust의 언더스코어가 나쁘다는 것이 아닙니다. 이 위치에서 언더스코어가 GlueSQL의 기능 계약보다 넓은 값을 받아들이는 것이 문제입니다. 이후 AST가 인자를 보관하지 않으므로 입력 정보가 사라집니다.

07 · Error Boundary

왜 ParserError가 아니라 TranslateError일까?

SQL 문법 자체가 잘못된 경우와, 문법은 맞지만 GlueSQL이 지원하지 않는 경우를 구분해야 합니다.

DELECT FROM test
ParserError
GLUE_TABLES(1)
TranslateError
SERIES(3)
Execute
DELECT는 SQL grammar에 없는 단어라 Parser가 거절합니다. GLUE_TABLES(1)은 sqlparser가 표현 가능한 SQL 구조지만 GlueSQL에는 해당 기능이 없으므로 Translator가 거절해야 합니다. SERIES(3)은 지원되므로 이후 단계로 갑니다.

08 · Learning Boundary

하나를 이해했다고 바로 기여 주제가 정해지는 것은 아니다

이번 실험은 Parser와 Translator의 한 경계를 이해한 사례입니다. GlueSQL 전체의 우선순위나 내가 맡을 이슈까지 결정한 것은 아닙니다.

WHAT I CAN EXPLAIN

이번에 확인한 것

  1. args의 None과 Some이 SQL 모양과 연결된다.
  2. Rust의 match 순서가 지원 입력과 오류 입력을 나눈다.
  3. 문법 오류와 미지원 기능 오류는 서로 다른 단계에서 발생한다.
WHAT I STILL NEED

아직 더 살펴볼 것

  1. Planner와 Executor까지 이어지는 실제 호출 흐름
  2. SQL fixture와 unit test를 나누는 프로젝트 기준
  3. 문서, 테스트, 코어 코드 중 내가 편하게 시작할 영역
지금 필요한 결정은 이슈 번호가 아니라 다음에 무엇을 읽어볼지다.
로컬에서 한 변경은 학습 사례로는 유효하지만, 곧바로 제가 맡을 기여 주제라는 뜻은 아닙니다. 지금은 무엇을 설명할 수 있고 무엇을 더 배워야 하는지 구분하는 단계입니다.
